# v2.0.4 — Abandoned-run admission policy design

## Decision

Do not implement "abandoned = interrupted". The current tracker inserts a run into `database.runs` at run start, and `close()` marks an active run as `interrupted` when a lifecycle boundary occurs. A later official summary can mark a run `ended` with result `left`. These are materially different states.

A safe "do not record abandoned runs" policy must therefore be a *delayed history-admission decision*, not an early deletion:
- Default disabled, preserving current behavior.
- Only eligible when a fresh, matching official summary explicitly reports result `left`.
- Optional minimum duration threshold is applied to the official summary duration, not an inferred client timer.
- If the official summary is missing, stale, rejected, malformed, or does not match the run, retain the run as interrupted/unknown.
- A prior official victory is never reclassified as abandoned by a later Endless continuation result.
- The option must not delete or rewrite any pre-existing historical run.

## Accounting and storage invariant

Today, runs are inserted at start and aggregate totals are updated through `A.Account(run)` with idempotent per-run ledgers. Simply removing a run after accounting would leave lifetime totals inconsistent; suppressing insertion before finalization would lose the active run on crash/reload.

Therefore implementation must first define a reversible tombstone/admission state and explicitly test:
1. left result below threshold (skip detailed history, no run/win/metric aggregate accounting);
2. left result at/above threshold (retain normally);
3. interrupted without official summary (retain);
4. official defeat/death (retain);
5. victory then Endless left (retain victory);
6. reload before summary (retain pending/interrupted);
7. repeated summary packets (idempotent);
8. backup/restore while a run is pending and after decision;
9. no automatic deletion of any historical run;
10. favorites/protected runs never eligible.

No code change is authorized until the above can be implemented without transiently corrupting totals or dropping crash-recovery state. Initial release default stays OFF.

## Next implementation approach

Prototype a pure decision helper that accepts only a validated matching official summary and duration; test it independently. Then integrate at one explicit terminal/finalization boundary with an accounting strategy proven by tests. Keep the raw source run until the decision is committed and backup-safe.

## Implementation checkpoint — eligibility only

`Tracker.lua` now exposes `A.AbandonedAdmissionEligible(run, minimumMinutes)`,
a side-effect-free predicate. It requires a finalized `left` result, a matching
retained official result with explicit hero and zone identity, and a finite
nonnegative official duration strictly below the configured minute threshold.
It fails closed for interrupted runs, victory/Endless continuations, rejected
summaries, favorites/protected markers, malformed input, and absent settings.
A synthetic offline regression matrix exercises those negative cases.

**Not enabled:** no UI toggle, automatic exclusion, aggregate subtraction,
history removal, tombstone, codec change or save migration has been added.
The helper is deliberately not called by the live lifecycle. Existing run
accounting remains unchanged. Eligibility is only one of the prerequisites:
before enabling exclusion we still need precise replay/restore tests covering
early `A.Account` calls and idempotent rollback of every cumulative ledger.

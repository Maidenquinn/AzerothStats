## Performance assessment and limits

- Export output is bounded to 8,192 bytes and rejects oversized documents instead of truncating JSON.
- Export serialization uses a fixed 13-metric allowlist and does not clone the full SavedVariables database, backups, raw event journal, gear links or tooltips.
- Historical run lookup and latest-run selection scan the retained run array (O(n)); the synthetic 1,000-run smoke test exercises correctness, not a measured native-client latency benchmark.
- CI's existing 100/500/1,000-run benchmark is for backup scaling, not a dedicated AZST1 serializer benchmark. Do not describe it as a serializer performance measurement.
- No persistent index or duplicate export cache has been introduced; the current scan avoids SavedVariables schema/migration risk.
- Native game memory/CPU and browser-client timings have not been measured in a controlled benchmark.

## Native identity conclusion

Observed evidence is consistent with a session-scoped native candidate: stable through five reloads within one run, counter advanced for a subsequent run, and candidate namespace changed after a full client restart. Endless retained the same local run/candidate in the observed sample. An earlier cross-zone pair showed a repeated candidate across two local IDs, so the candidate must not be treated as a globally unique key.

Therefore: `nativeRunId` remains null in AZST1 and no native candidate is persisted or auto-linked. Rakesh must confirm the exact same-upload/session matching scope before any future opt-in persistence or correlation rule.

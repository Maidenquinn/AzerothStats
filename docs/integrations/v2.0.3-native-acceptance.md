# v2.0.3 native continuity and export acceptance (draft)

Use an isolated client profile and back up the full AzerothStats SavedVariables file before installing a PR artifact. Do not send the raw save or screenshots containing player names to external services. Record game version, desktop/browser client, PR commit, and ZIP SHA-256.

## Baseline and compatibility
1. Install official v2.0.2, retain a copy of its save, and record run count, last run ID, backup counts, settings, and file size. Install the v2.0.3 candidate without deleting the save.
2. Confirm all old runs and both backup collections remain readable; do not claim pass from a synthetic fixture alone.
3. Compare a newly completed run's exported numeric fields against the native UI. Missing fields must remain unavailable rather than zero. The current `ExportRunV1` function is an in-memory API only; do not expect a file on disk yet.
4. Check that the new module creates no additional SavedVariables root and does not alter a run when its returned table is changed.

## Continuity matrix
| Case | Procedure | Expected result |
| --- | --- | --- |
| Single reload | Begin a run, record class/zone/heroic, elapsed time, kills, and local ID, then /reload | One retained run, monotonically accumulated counters, no duplicate finalization |
| Repeated reload | /reload three times in the same run | Same local run when continuity is supported, no duplicate history |
| Ready transition | End or leave a run, observe ready, start a new run with same class/zone | Distinct run; old run retained |
| Time reset | Start a new run with identical class/zone/heroic and reset native timer | New run, never merge on reused numeric native ID |
| Terminal then endless | Complete official victory, continue, observe another terminal summary | No double accounting; original victory retained |
| Crash | Close client abnormally during a run, reopen | No deletion of previously flushed history; newly unflushed observations may be lost |
| Low FPS | Run under load, observe partial marker | No invented completeness, compare native final summary |
| Co-op | Play with and without second addon installed | No mandatory dependency or automatic network transfer |

## AZS_ZONE.run observation matrix
For each state (ready, active, /reload, death, victory, new run, full restart), record **type**, presence, whether it changed, and whether it matched the previous state. Use a local diagnostic only; redact any personal data. Repeat on desktop and browser if possible. A reused numeric value is not sufficient to merge two runs.

## Acceptance gates
- Full offline CI and native Lua 5.0 checks green at exact PR head; updated SHA256SUMS verified.
- No unapproved change to the v2.0.2 persistence schema or backup roots.
- Rakesh reviews export field names, timestamp units/provenance, and safe correlation strategy.
- In-game tests confirm reload continuity, FR/EN, and no regressions.
- Only then build and deliver a test ZIP; no public release without owner approval.

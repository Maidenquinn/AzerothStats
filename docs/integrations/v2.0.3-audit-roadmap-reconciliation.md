## Findings, ordered by priority

### P1 — Native correlation remains observational
`AZS_ZONE.run` is observed in both addons but its uniqueness, reuse and behavior through reload/ready/endless remain unproven. `nativeRunId=nil` in retained projections is the correct fail-closed behavior. Never add automatic matching based only on this field.

### P1 — No end-to-end integration
The current API returns an in-memory Lua table. WoW Logs AS v0.2.2 builds its own `WLAS` JSON code with `gameRunId`; it does not consume the Azeroth Stats schema. A successful export unit test must not be represented as successful WoW Logs ingestion.

### P1 — Test gaps for actual lifecycle and data safety
Add fixtures covering real status/result vocabularies, ready transitions, repeated reload, interrupted/terminal/endless, coop, old save with missing fields, corrupt runs, pruned history, and post-restore state. Compare actual user save in isolated environment only with consent and redaction. Add explicit tests that no SavedVariables roots or input tables change.

### P2 — Export complexity and malformed collection handling
`ExportRetainedRunV1` scans the retained history O(n), currently bounded by 10–1000 runs; reasonable for on-demand use. A duplicate ID returns nil, but Lua `ipairs` stops at the first hole; malformed sparse arrays could hide later duplicates. Decide whether the DB validator guarantees dense arrays; otherwise reject sparse input or use a bounded robust traversal. No new persistent ID index justified for a rarely called API.

### P2 — Data quality and semantic fidelity
The lifecycle allowlists may omit legitimate `summary.result` values; verify actual vocabulary and extend tests before relying on outcome. `startedAt`/`endedAt` have undocumented clock units; `provenance=retained-run` does not imply native-observed. Numeric metrics currently allow negatives by design, which should be documented and assessed field by field.

### P2 — Probe UX and privacy
`/azstats interop probe` is a developer-only diagnostic, prints a raw candidate to chat, has English-only strings, and is not tested in the actual game. It does not persist or transmit anything. Decide whether it should remain hidden behind diagnostics or be localized for public v2.0.3.

### P3 — Efficiency and coverage
No new 1 Hz polling or duplicated combat history was introduced. Export allocates 13 small metric tables per explicit invocation, acceptable for on-demand use. Benchmark 10/100/1000 retained runs and repeated exports, with memory/time thresholds, before release. Add a representative fixture and assert the export is JSON-safe only after choosing a serialization contract.

## Revised implementation sequence and gates
- **Gate A:** resolve findings in synthetic tests, particularly lifecycle vocabulary, sparse/duplicate history, privacy and legacy fixture; preserve checksums and green CI.
- **Gate B:** collect safe native observations on desktop/browser and repeated reload/new run; verify `AZS_ZONE.run` reuse and correlation with WoW Logs AS `gameRunId`. No forced merge.
- **Gate C:** agree with Rakesh on actual importer/uploader format, correlation policy, privacy consent and missing/zero semantics. Implement explicit handoff only after this contract exists.
- **Gate D:** benchmark export and old-save continuity, verify FR/EN and existing UI, obtain CI-green PR ZIP and owner in-game acceptance.
- **Gate E:** prepare changelog and English Discord message; merge and release only after explicit owner approval.

## Audit limitations
GitHub Actions results and inspected code were verified through the connector. No native client, uploader backend, production WoW Logs website, or user SavedVariables were exercised in this audit. No performance timings or zero-regression guarantee can be claimed.

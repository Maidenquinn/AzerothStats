# v2.0.4 Lot A — native acceptance carried forward and CI replay

The maintainer confirmed on 2026-11-12 that the native identity, reload continuity, preservation, backups and WoW Logs direct-read use cases had already been manually accepted. Do not demand that these gameplay checks be repeated merely because the discussion moved.

## Automated coverage added

`AzerothStats/tests/interop_lifecycle_contract.lua` is run by `tools/checks.py` and tests synthetic observations of:
- Opaque native run candidate stable between two live packet observations (the documented /reload case).
- A different preallocated candidate in the next lobby does **not** backfill either completed or interrupted saved runs.
- AZST1 export remains a separate manual projection; existing SavedVariables `summary`, `stats`, `equipment`, and `timeline` fields are unchanged.
- The manual and automatic backup roots preserve object identity and content.
- The synthetic database and snapshots have unchanged signatures after export.

These are **contract regression tests**, not a claim to simulate the actual game client. The tested current behavior deliberately does not persist native IDs or populate `nativeRunId`; this is an explicit historical gap in the v2.0.3 interop implementation. Enabling native-ID persistence would require a separately reviewed lifecycle change and new direct-reader compatibility tests, not silent retroactive attribution.

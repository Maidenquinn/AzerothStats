# Azeroth Stats v2.0.4 — Community feedback, scope and safety gates

Base: main, v2.0.3 integration. Branch: `feat/v2.0.4-community-feedback`.

## Source: Community Discord feedback (2026-11-10)

1. Square icon: default theme appears slightly off-center.
2. Round icon: broken in multiple themes; toggling on/off produces distinct breakage in Grimoire and Warcraft themes.
3. Replacement icon beside character name/class is questionable and needs UX review.
4. Analyze Run > Highlights list is too short.
5. Settings > Optional analyses has a spelling issue and insufficient explanations, especially Effects (buffs/debuffs?).
6. Options > Behaviour > Record sounds does not explain which sounds or why.
7. Some earlier feedback remains unresolved; request an explicit feedback reconciliation checklist.
8. SavedVariables around 100 MB for 144 runs, with longer loading times reported (correlation, not yet proven causation). Owner observed about 84 MB for ~300 runs after prior optimization; measurements are not directly comparable without data breakdown.
9. Suggested compact color representation (instead of verbose floating-point r/g/b tables), string dictionaries for repeated location/spell/state/event labels, and compact positional arrays for predictable statistics.
10. Requested optional co-op talent and equipment capture, subject to native API support.
11. Requested option to avoid recording abandoned runs, optionally only when shorter than configurable minutes.
12. Owner mentioned a future leaderboard; no leaderboard specification or backend/privacy contract yet.

## Implementation lots

### P0 — Data integrity and measured size reduction
- Reproduce size growth with synthetic and anonymized real-world shaped data. Report bytes by root, run, timeline, events, backups, optional analyses and repeated strings.
- Distinguish active ledger vs manual and auto backups. Check whether file size is duplicated through backup rotation.
- Measure native save/load and frame latency separately; do not assert file size causes slow loading without profiling.
- Prototype compact color and string-table representations in isolated, versioned fixtures; benchmark bytes, encoding/decoding CPU and memory. Prefer only changes with meaningful net savings.
- Guarantee read compatibility for all v2.0.2/v2.0.3 data and existing backup restore. No in-place destructive rewrite, lossy truncation, silent pruning or irreversible migration. Include round-trip, crash-interruption, malformed input, mixed-version, duplicate run and large-history regression cases.
- Preserve v2.0.3 AZST1 export semantics and external WoW Logs AS SavedVariables direct-import compatibility; a new internal encoding must not silently break the existing consumer.
- Any optional compaction must include explicit opt-in, backup and a documented rollback strategy before release.

### P1 — Icon and settings UX
- Matrix: default, Grimoire, Warcraft and every other supported theme × square/round × toggle on/off × reload × scale/resolution. Verify both native and standalone addon environments.
- Fix default square alignment and round icon lifecycle; inspect anchors, textures, clipping, alpha, mask and stale frame references. Review character name/class icon replacement.
- Make Analyze Run Highlights list scroll or expand without hiding entries.
- Correct Optional analyses spelling, and provide precise, truthful help for Effects and Record sounds based on the actual collection code. Do not invent capabilities.

### P2 — Abandoned run policy
- Configurable toggle to skip abandoned runs, with optional minimum duration in minutes; default OFF to preserve existing behavior.
- Distinguish abandoned from defeat, victory, interrupted, Quit Game and incomplete runs based on actual game events. Avoid treating an uncertain status as abandoned.
- Specify whether skipping affects run history only or cumulative totals and backups; require consistent accounting and tests. Never delete existing historical runs implicitly.

### P3 — Co-op information
- Audit available native APIs for other players' talents and equipment. Do not promise collection if unavailable.
- If supported, make capture opt-in, bounded and privacy-conscious, and measure storage cost before enabling.

### P4 — Leaderboard discovery, separate decision
- Clarify offline vs online, score definition, anti-cheat, identity/privacy, synchronization and moderation. Do not introduce network access in this lot without a separate explicit decision.

## Acceptance gates
- No data loss across migrations, reloads, backups and restores.
- Measurable size reduction against representative fixtures, with documented CPU/load tradeoffs.
- No AZST1 contract regression or WoW Logs direct-import breakage.
- FR/EN copy and every theme tested.
- User receives a CI-green test ZIP before any merge or release.
- No merge/release without explicit approval.

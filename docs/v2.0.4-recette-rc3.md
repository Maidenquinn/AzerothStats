# Azeroth Stats 2.0.4-rc3 — recette native (12 novembre 2026)

**Statut : release candidate de recette, PAS une release stable.** Branche `feat/v2.0.4-community-feedback`, PR #36. Ne pas merger ni publier officiellement avant validation de la recette. Ce document accompagne le ZIP produit par GitHub Actions.

## Validation de la branche

Le lot A dispose de régressions automatisées sur l'identité native candidate, le changement d'ID en lobby, les champs lus par WoW Logs et les racines de sauvegarde ; la recette manuelle de continuité a déjà été validée précédemment par le mainteneur. Les scénarios visuels propres à RC3 restent à vérifier dans le client. Le paquet de la PR est nommé `AzerothStats-2.0.4-rc3-pr-review`.

## Nouveaux scénarios RC3 (lots B et C)

- **B — Grain carré :** sur chacun des cinq thèmes, comparer icône ronde puis carrée puis ronde, avant et après `/reload`. Vérifier qu'aucun carré résiduel n'apparait derrière l'anneau, y compris lorsque l'opacité est faible ou nulle.
- **C — Sauvegarde automatique identique :** entre deux parties, effectuer deux sauvegardes auto sans modifier la base ; confirmer que la seconde est signalée déjà à jour et que le nombre de snapshots n'augmente pas. Après une partie terminée, confirmer qu'une nouvelle sauvegarde distincte est créée et restaurable.
- **C — Historique :** vérifier compteurs, favoris, classements, runs, exports AZST1 et anciennes sauvegardes inchangés ; aucun compactage ni suppression automatique n'est introduit.
- **Mesure :** relever taille en octets des fichiers SavedVariables après fermeture normale. La RC3 optimise le travail d'une sauvegarde identique mais ne promet aucune diminution des octets sur disque.

## Avant installation — obligatoire

1. **Quitter complètement** Azeroth Survivors (pas seulement un /reload). Faire une copie séparée hors du dossier du jeu des fichiers SavedVariables existants. **Sur le client Azeroth Survivors Reborn de ce testeur**, la sauvegarde est regroupée dans `Jeu\\benilla-config\\saved\\AzerothStats.lua` : il peut n'y avoir qu'**un seul fichier**, même si le `.toc` déclare trois racines Lua (`AzerothStatsDB`, `AzerothStatsBackup`, `AzerothStatsAutoBackup`). Ne pas inventer ou attendre trois fichiers physiques. Ne jamais transmettre ces fichiers bruts publiquement : ils peuvent contenir des noms de joueurs.
2. Conserver le ZIP officiel 2.0.3 pour revenir en arrière. Ne pas lancer deux copies de l'addon simultanément.
3. Extraire le ZIP de recette : il doit contenir **un seul dossier `AzerothStats/`** avec `AzerothStats.toc` directement dedans. Remplacer l'ancien dossier de l'addon, **pas** les fichiers dans WTF/SavedVariables. Vérifier `## Version: 2.0.4-rc3`.
4. Démarrer le jeu et vérifier l'ouverture de l'addon, les statistiques préexistantes et l'absence d'erreurs Lua.

La sortie JSON ne lit pas les données des joueurs. Garder les sauvegardes brutes hors Discord/GitHub ; partager seulement les trois tailles et le contexte (nombre de runs, sauvegardes, version).

## Cas négatifs à signaler

- Snapshot manquant/corrompu, conflit de version, run interrompu sans résumé officiel, résultat `left` non reconnu, record remis à zéro, changement de thème qui casse l'icône.
- Les runs abandonnés **ne sont jamais supprimés** dans cette RC et restent dans les totaux cumulés. `hide` agit uniquement sur l'historique à l'écran.
- L'interface native et les performances réelles ne sont **pas** certifiées par CI. Les macros et commandes de diagnostic restent locales ; aucune synchronisation réseau automatique.

## Rollback

1. Fermer complètement le jeu.
2. Remplacer seulement le dossier addon `AzerothStats` par le dossier stable 2.0.3.
3. En cas de problème de données, restaurer les **trois** fichiers SavedVariables copiés à l'étape initiale, jeu fermé. Ne pas écraser les sauvegardes initiales avec des copies plus récentes.
4. Vérifier les données en jeu. Si un problème est reproductible, fournir ID Rxx, thème/langue, résultat, captures et erreurs Lua (sans SavedVariables brutes).
